# 1. 测试分类
## 1.1 开发阶段分： 
单元测试-----> 集成测试 ------> 系统测试（含冒烟和回归）----> 验收测试（交付测试）

冒烟（测主要功能）----> 系统测试 ----> 回归

验收测试：符合验收医药局文档，展示系统满足原始需求

## 1.2 代码可见度
1. 黑盒：功能测试，只关心输入输出
2. 白盒：接口测试的一种
3. 灰盒：多用于集成测试阶段，关于输入输出 + 接口 == 功能 + 接口

## 1.3 是否运行
1. 静态测试：不运行，检查语法、结构等，包括对需求说明书、流程图等分析
   
   （衡量指标：功能性、可靠性、可用性、可维护性、可移植性、有效性）
2. 动态测试：需要分析运行效率、正确性、健壮性等
   
   组成元素：构造测试用例、执行程序、分析程序输出结果


## 1.4 测试对象
1. **性能测试**：需求规格说明书为标准，主要包含**资源利用**、**日志文件**、**响应时间**、**吞吐量（TPS）**
2. **安全测试**：
3. **兼容性测试**：最常见的为**浏览器**的兼容测试，不同浏览器在css、js**解析不同**，最终页面呈现也不同
4. 文档测试
5. 易用性测试：用户体验、交互
6. **业务测试**：模仿真实使用的工作流程
7. **界面测试**：
8. 安装测试：安装与卸载
9. 内存泄漏测试：可使用工具帮助检查
